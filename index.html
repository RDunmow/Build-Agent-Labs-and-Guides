A ServiceNow Studio Workshop

Build Agent &
the Pub Quiz

A walk-through of building a complete Pub Quiz Manager application in ServiceNow Studio, one prompt at a time.

This workshop walks participants through building a Pub Quiz Manager application in ServiceNow Studio using Build Agent. The session uses progressive prompts that build on each other, starting with a simple foundation and ending with workflow automation and a Now Assist integration.

The structure is designed so participants can see Build Agent extend an existing app, not just create one from scratch — which is where the real magic shows.

Session Structure
  1. § 1Foundation: tables, relationships and some test data
  2. § 2Creating an admin workspace, extra question functionality, a workflow
  3. § 3A new UI for the teams to interact with
  4. § 4Automating the current question and running the quiz
  5. § AAppendix A — UI errors: helping Build Agent fix them
  6. § BAppendix B — Finding the URL of generated pages

Section 01 — FoundationLet's get creating our first app

Problem: we want to create an application to manage local pub quizzes, and we've decided to try to build it using AI. So first we need to decide what the problem is — we want our app to do the following:

  1. Setup a quiz, location etc
  2. Give the quiz some structure
  3. Holding questions for each round and the answers
  4. Capture the team names
  5. Capture the answers given

From this, we can start to create our first prompt:

Build a scoped application called Pub Quiz Manager that helps someone organise and run pub quizzes from start to finish. The app should support: - Setting up a quiz, including when and where it's happening and who's hosting - Structuring a quiz into multiple rounds, each with its own theme or category - Adding questions and correct answers to each round - Registering teams who are taking part - Capturing each team's answers and tracking how they score Design the data model and user experience that best supports this. The primary user is the quiz host, who needs to manage quizzes before and during the event.

Section 02 — The workspaceLet's create a workspace

Thankfully we are using App Engine, so we could use Workspace Builder to help us here — but we are going to ask Build Agent to create us one. This is a simple prompt to get us started:

Create a workspace for the quiz manager to review the events, teams, questions and answers. I should be able to update and manage questions from this.

Build Agent will now go away and create a new workspace. It will probably look pretty basic, but we can work on that:

Opening the workspace, we see a simple UI, but the table definitions carry across:

Adding extra fields to the question table and adding a workflow

The current quiz design makes all questions active at the same time. We want to eventually add an interface for the teams to play the quiz on, so we need to add some additional information to the questions table and also add a workflow that sets all the questions to false.

Currently when a quiz is active all the questions are also active. I want to change the questions so that only one question is active at a time. I want this so that we can build a quiz UI for all teams to see the same question at the same time. Can you add a current question flag to the questions table and also make a workflow that when a quiz is made active will make sure all the questions are not active.

Now even though we had asked for a workflow, Build Agent in its plan decided to create a business rule, so instead of just approving the plan, which looked like this:

…we ask Build Agent to create a workflow with a prompt like this:

I asked you to create a workflow not a business rule to set the is_current flag on the questions table to false. Please correct this.

Build Agent will go away and make the appropriate changes to its plan, which now looks like this:

Now that we are happy with the plan, let's approve it. Once that has completed, we have a new field added to the questions table:

…and we have a new workflow that has been created:

Pattern worth remembering: Build Agent's first plan isn't always exactly what you asked for. Always read the plan before approving — a short clarifying prompt is much cheaper than a rollback.

Appendix AUI errors — helping Build Agent fix them

Sometimes when Build Agent is creating UI pages, especially in frameworks such as React, the page can compile and look fine, but at runtime you can get errors with the page not loaded.

So if for any reason you don't get a working page, check the JavaScript console for errors. If you see one, report it back to Build Agent — for me I had an issue with line 120, unexpected token '>':

Explain the error to Build Agent, give as much information as you can, don't be afraid to give a whole dump from the JavaScript console:

There is an error on the x_snc_pub_quiz_o_0_quiz_player.do page at line 150, the error returned was "SyntaxError: Unexpected token '>'"

Appendix BHow do I navigate to the pages that have been created?

Normally, when Build Agent creates a new asset such as a page, it will tell you about this in the summary — but how do you find what the actual page URLs are when that summary has long gone?

In ServiceNow Studio, if you scroll down to the User Interface section, you will see the UI pages section:

Each new page that you have asked for is there. If we click the quiz_control page, Studio will open part of the IDE — as this is a React App, the menu on the left has changed, but the endpoint of the page is shown:

To get back to the previous view, click the Apps icon (just below the + sign on the left) — this will return you back to Studio.

If you grab the endpoint and add it to your server URL, such as:

https://{your_servicenow_system}/x_snc_pub_quiz_o_0_quiz_control.do

…the page will now show.
